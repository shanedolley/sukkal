Privacy policy

Effective 19 October 2026

Sukkal's use and transfer of information received from Google APIs to any other app will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

Who runs Sukkal

Shane Dolley operates Sukkal as an individual, in Queensland, Australia. Contact: shane@koinon.com.au.

Sukkal is a personal assistant with one owner per installation. This policy covers the installation at app.sukkal.app and this website. Somebody who runs their own copy of Sukkal is the operator of that copy, and this policy does not cover it.

Google user data

The owner connects a Google account on the Connections screen and chooses which services to allow: Gmail, Calendar, Meet or Drive. Sukkal asks Google for the permissions of the chosen services and no others. Sukkal reads this data from the connected account:

  • The email address of the account, so that several connected accounts can be told apart.
  • Mail messages and threads in Gmail, and the labels on them.
  • Events in Google Calendar, including the events that held a Meet call.
  • Documents and files in Google Drive.

Sukkal uses this data for one purpose: to serve the owner who connected the account. It builds the owner's daily briefing, labels mail, drafts replies, links meetings to projects, keeps a memory of the people, decisions and commitments in the material, and answers the owner's questions from that memory. Sukkal shows the data only to the signed-in owner.

Permissions requested

Google calls these permissions scopes. Sukkal asks for five and no others. It always asks for the first two. It asks for each of the others only when the owner allows the matching service.

Identity, always

  • openidSign in with Google, so Sukkal knows which account consented.
  • https://www.googleapis.com/auth/userinfo.emailRead the address of the account, to name the connection and tell accounts apart. Sukkal keeps the address and nothing else from the answer.

Gmail

  • https://www.googleapis.com/auth/gmail.modifyRead mail, apply labels, and create reply drafts for the owner to edit and send. Sukkal never sends mail unprompted, and it does not use this scope to delete mail.

Calendar and Meet

  • https://www.googleapis.com/auth/calendar.eventsRead and edit events, and answer invitations for the owner. Meet needs no scope of its own, because Sukkal reaches a Meet recording through the calendar event that held it.

Drive

  • https://www.googleapis.com/auth/driveRead, create, edit and reorganise documents when the owner directs. Sukkal never deletes a file.

Where data is stored

Sukkal stores data in a PostgreSQL database on a server that Shane Dolley owns, in Queensland, Australia. It uses no cloud database.

The tokens that let Sukkal reach a Google account are sealed with AES-256-GCM before they are stored. The key is kept outside the database, in a file with restricted permissions on the server. A copy of the database alone does not open them.

The owner signs in with a password, which Sukkal stores only as a salted scrypt hash. Cloudflare Access also asks for the owner's identity before a request reaches the server.

Who receives data

Sukkal sends data to a provider below only when the owner has connected that provider. Sukkal does not sell data to anyone.

  • Anthropic runs the Claude model. It receives excerpts of mail, events and documents when Sukkal classifies mail, drafts a reply, extracts facts or answers a question. It receives them through the owner's Claude subscription or API key.
  • Voyage AI turns text into embeddings, so that search finds meaning and not only exact words. It receives chunks of the owner's mail, documents and facts.
  • Resend sends Sukkal's own system mail, which today is the password reset link. It receives the owner's sign-in address and the link. It receives no Google user data.
  • Cloudflare carries traffic between a browser and the server through a tunnel, for the application and for this website. The owner's pages and the data on them cross Cloudflare's network while in transit.

These providers may process data outside Australia. Sukkal sends each of them only what the task needs. Each provider keeps data under its own terms, which Sukkal does not control.

Sukkal does not train models. It sends text to a model provider to get one answer for the owner. Sukkal does not use Google user data for advertising, and it runs no analytics or advertising tools.

Sukkal has one owner and no other users, support staff or reviewers. The operator can reach the database, and on this installation the operator is the owner.

Retention and deletion

Sukkal keeps a connection's tokens until the owner removes the connection. It then deletes the stored tokens.

Sukkal's memory keeps what it learned from mail, events and documents until somebody deletes it. It retires a fact that is no longer true and keeps the record, so the history stays. Removing a connection stops all new reading. It does not by itself delete what Sukkal stored earlier.

To have stored data deleted, write to shane@koinon.com.au. The operator deletes it from the database. A backup copy of the database holds the data as it stood when the copy was taken.

Revoking access

Use either route. Neither needs the other.

  1. In Google: open myaccount.google.com/permissions, choose Sukkal, and select Remove access.
  2. In Sukkal: open the Connections screen and remove the connection. Sukkal tells Google to revoke the token first. If Google does not confirm, Sukkal keeps the connection, says why, and lets the owner try again. Once Google confirms, Sukkal deletes the stored tokens.
